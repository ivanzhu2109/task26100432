# econtrace — 经济关联门槛追溯组件

进程内 Go 库，供税务人员补录、更正销售流水后查询历史状态。
调用串行（非并发安全），无持久化，金额一律使用整数分，门槛比较不使用浮点数。

## API

- `New(map[string]Thresholds)`：以各辖区销售额/笔数门槛初始化（正整数，运行期不变）。
- `Upsert(Event)`：新增或以相同 id 完整替换流水（可改时间、辖区、类型、金额，含跨年移动）。
- `Remove(id)`：删除流水，返回是否存在。
- `Status(jurisdiction, at)`：查询 at 所在 UTC 自然年从年初到 at（含 at）的状态：
  累计净销售额、销售笔数、级别（正常/预警/已建立关联）、本年度预警与关联的首次触发流水及时间。

规则：销售金额为正计 1 笔，退款金额为负计 0 笔；预警 = 金额或笔数达门槛 80%
（`ceil(4T/5) = T - T/5` 整数计算），关联 = 任一指标达 100%，等于边界即命中；
年度内级别只升不降；同一笔可同时首次触发两个级别；新年不继承。
年度内排序按 (发生时间, id 的 UTF-8 字节序)，写入顺序不参与裁决。

## 实现与复杂度

每个 (辖区, 年度) 一棵按 `(时间, id)` 定序的 treap（随机优先级堆），
子树聚合金额/笔数的合计与前缀和最大值：

- `Upsert` / `Remove`：treap 插入/删除，期望 O(logN)。
- `Status`：按时间拆出前缀（split），在聚合上 O(logN) 定位首个使前缀和
  越线的流水（金额、笔数各一次，取较早者），随后 merge 还原，期望 O(logN)。
- 常驻内存 O(N)。任何操作都不做全年度扫描、排序或重放，无定期全量重建；
  每次变更返回后即可查询。

## 测试

```sh
go test ./...                 # 全部测试
go test -run TestScale -v     # 规模测试（含耗时输出）
```

- `tracker_test.go`：80%/100% 边界 + 退款回落、同一微秒不同 id 的字节序裁决、
  级别不回降、删除关键销售后越线撤回、补录/更正使触发点后移与前移、
  年度独立与跨年移动、辖区隔离。
- `replay_test.go`：小规模逐笔重放参考实现，固定种子混合补录/替换
  （含跨辖区、跨年移动）/删除/历史查询，逐项比对累计值、级别与两个首次触发点。
- `scale_test.go`：30 万条流水集中在一天（笔数门槛不可达），随后 1 万次
  早期更正（加码/还原/删除首笔）与分布于全天的历史查询交替执行，
  金额首次越线点在三种闭式位置间移动并逐项断言。固定种子，可重复运行。

本机耗时记录（Apple Silicon，Go 1.27.1）：

- 插入 300,000 条：约 164–168 ms（≈180 万 ops/s）
- 10,000 次更正+查询交替：约 19–20 ms（≈50 万 ops/s）
