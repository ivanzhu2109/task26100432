# task26100432 — 经济关联门槛追溯组件（Go 进程内库）

税务人员补录、更正或删除销售流水后，可查询任一辖区在任一历史时刻所在
UTC 自然年的累计净销售额、销售笔数、关联级别（正常 / 预警 / 已建立关联），
以及当年首次达到预警与建立关联门槛的流水 id 与时间。

## 运行

```sh
go test -count=1 -v .          # 全部测试（含规模测试，打印耗时）
go test -run TestScale -v .    # 只跑规模测试
go test -count=3 .             # 重复运行验证可复现
```

## 设计

每个（辖区, UTC 自然年）对应一棵 **treap**（随机优先级笛卡尔树），
按键 `(发生时间, id 的 UTF-8 字节序)` 排序——与裁决顺序完全一致，
写入顺序不参与。节点子树维护四项聚合：

- `sum`：金额合计；`count`：销售笔数合计；
- `maxPref` / `maxPCnt`：子树中序序列上金额 / 笔数**前缀和的最大值**。

- **Upsert / Remove**：按 id 定位旧流水（全局 `map[id]Event`），先从旧
  （辖区, 年）树中摘除再插入新树，替换天然不保留双份贡献；O(log N) 期望。
- **Status(jurisdiction, at)**：按时间把树分裂成 `≤ at`（含 at 时刻全部
  id）与剩余两棵，在前缀树上读 `sum`/`count` 得累计值；用 `maxPref` 做
  树形二分，O(log N) 找到“首个使金额前缀 ≥ 目标”与“首个使笔数前缀 ≥ 目标”
  的流水，取较早者为首次触发点；随后把两棵树合并回去。
  级别 = 前缀内曾达到的最高级别，天然满足“达到后不因退款降低”，
  又完全由当前有效账本决定，更正 / 删除可令触发点前移、后移或消失。
- **80% 门槛**：`warn = ceil(4×threshold/5)`，全程整数比较，无浮点。

## 复杂度

| 操作 | 时间（期望） | 说明 |
|---|---|---|
| Upsert / Remove | O(log N) | treap 分裂 / 合并 + 哈希表 |
| Status | O(log N) | 一次按时间分裂 + 两次树形二分 + 合并 |
| 内存 | O(N) | 每条流水一个节点 + 一个哈希表项 |

任何操作都不做全年度扫描、排序或重放，也没有周期性全量重建。

## 耗时记录（Apple Silicon，go1.27.1，固定种子可复现）

- 规模测试：30 万条流水（同一辖区同一天）插入 **≈0.20s**（≈150 万条/秒）；
  随后 1 万次“早期更正 + 全天分布历史查询”交替 **≈25ms**
  （≈2.5µs/轮，约 39 万轮/秒）。
- 随机差分测试：3 万步混合补录 / 替换（含跨辖区、跨年移动）/ 删除 /
  历史查询，与逐笔重放参考实现逐项对比，≈1.0s 通过。
- 全套测试 `go test -count=1 .` ≈2.3s。

注：本机沙箱偶发 `~/Library/Caches/go-build` 条目损坏，可用
`GOCACHE=/private/tmp/gocache go test ...` 绕开。
